# ⑫ orientation report — recursive delegation / delegation-depth control (durable record)

Read-only orientation; repo zero-byte; no reviewer dispatch; one inert
first-hand probe (probe-evidence.md). Verdict and abstraction were
owner-accepted; this file is the durable record of the eleven deliverables.

1. **Doctrine map.** delegation-and-review was a two-party model
   (dispatcher ↔ worker) with every rule addressed to the dispatcher:
   bounded fan-out binds the DISPATCHER's review capacity; the §2 Rules
   field's worker prohibitions carried no re-delegation clause; child-scope
   ⊆ parent-scope existed nowhere; "operator-owned dispatch layer" (the
   execution-principal bullet) had no defined transitive semantics; the
   `[verified: ran/read]` tags had no defined subject. Already covered
   downstream: findings-are-claims (reproduce/audit/coverage/settled-tree),
   self-report-never-advances, content≠instructions — a chain insensitive
   to delegation depth. The execution-principal bullet already covered
   UNAUTHORIZED spawn (an exec-class act outside the envelope ⇒
   compromised lens); it never owned identity/count/family accounting.
2. **Execution model (first-hand).** Agent-capable subagent types carry
   the full toolset including Agent ⇒ mechanically recursive; two
   restricted types have Agent removed (a per-type harness precedent). An
   inert two-level spawn probe SUCCEEDED (real invocation). The harness
   default-backgrounds a child's spawn — the child returned while its
   grandchild still ran, no upper-level handle (the orphan-principal
   DISCOVERY, expressly not activated). Workflow already has one-level
   nesting, lifetime caps, and a user opt-in clause. External reviewer
   CLIs execute freely under fs-read-only sandboxes ⇒ recursive spawn
   there never passes through any harness delegation mechanism ⇒ a depth
   cap is unenforceable (the L1 refutation).
3. **Current examples.** All repository practice is depth-1
   orchestrator-mediated dispatch; one legitimate two-level shape exists
   (an agent invoking another model's CLI as a mechanical helper), which
   control cases D11/D12 pin.
4. **False-clear + clearers.** Type 1 (external reviewer secretly
   consulting another family's CLI under a packet-only expectation) is
   already covered by the execution-principal bullet. Type 2
   (orchestrator-side subagent critic silently fanning out to sub-critics,
   synthesizing, tagging `[verified: ran]`) was covered by NO text — every
   outer check passes while principal count, family accounting, and
   evidence provenance are silently wrong. Clearers: deterministic
   helpers; operator-approved trees; mechanical subtasks with full
   provenance; two levels per se are never a finding.
5. **Verdict: B. PARTIAL-GAP** — the gaps are real (type-2 false-clear)
   but sit on natural extension points of existing clauses.
6. **Abstraction: L2** (delegated-authority / contribution-provenance
   propagation). L1 rejected (unenforceable on external CLIs; would ban a
   legitimate shape; harness backstop already exists). L3 rejected (all
   practice is depth-1; no evidence a trust graph earns its place).
7. **Minimal invariant candidate** — superseded by the owner's reframed
   canonical principle and the frozen v2 design (design-v2.md).
8. **Canonical home:** delegation-and-review §2 (worker conduct) + §3

9. **Overlap/dedup:** the CMR author-family clause is the author-side
